# kubev-beginner-labs

Companion lab manifests for the **KubeV Beginner** course on HubLMS.

This directory will be published at [`kubermatic/kubermatic-academy/tree/main/kubev-beginner`](https://github.com/kubermatic/kubermatic-academy/tree/main/kubev-beginner). Until publication, the recording pipeline references it via the `$LABS_DIR` env var (default `$HOME/kubev-beginner-labs`, set in the learner's shell rc or by `chapter-01-prerequisites/pre-record.sh`).

## Attribution

Several files here were copied or adapted from Hubert Ströbitzer's in-person training repo at [`cloudnativetrainings/kubev`](https://github.com/cloudnativetrainings/kubev). Each adapted file's header documents its source and the specific changes made. Hubert's repo is the canonical reference for Kubermatic-delivered trainings; this scaffold is a subset, reshaped for the self-paced beginner course.

## Layout

Folders exist only for chapters that ship manifests. Ch01 (Prerequisites), Ch02 (K8s Refresher & CRDs), and Ch09 (Virtualization Dashboard) are inspection- or browser-only — they have no scaffold folder. The number prefix on each folder is its position in the manifest-bearing sequence (not the chapter number).

| Folder | Chapter | Key files |
|--------|---------|-----------|
| `02_install/` | Ch03 — Install Kubermatic Virtualization | `cluster.yaml.template`, `metallb.yaml` |
| `03_first-vm/` | Ch04 — Your First Cloud-Native VM | `vm.yaml` (Ubuntu 22.04 + cloud-init password auth) |
| `04_vm-lifecycle-ssh/` | Ch05 — VM Lifecycle & SSH | `vm.yaml.template` (Ubuntu 22.04 + cloud-init SSH key) |
| `05_vm-networking/` | Ch06 — VM Networking Basics | `web-svc.yaml` |
| `06_vm-storage/` | Ch07 — Storage Basics for VMs | `data-disk.yaml`, `ubuntu-dv.yaml`, `ubuntu-vm.yaml.template`, `ubuntu-vm-datavolumetemplates.yaml.template` |
| `07_kkp-integration/` | Ch08 — KKP Integration | `hello-web.yaml` |
| `08_teardown/` | Ch10 — Teardown | `teardown.sh` (node-level, optional) |

## `.template` files

Files ending in `.template` contain `$VAR` placeholders expanded via `envsubst`. The specific env vars per chapter:

| Template | Env vars |
|----------|----------|
| `02_install/cluster.yaml.template` | `$CP_INTERNAL_IP`, `$WORKER_INTERNAL_IP`, `$METALLB_RANGE`, `$SSH_KEY_PATH` |
| `04_vm-lifecycle-ssh/vm.yaml.template` | `$SSH_PUBKEY` |
| `06_vm-storage/ubuntu-vm.yaml.template` | `$SSH_PUBKEY` |
| `06_vm-storage/ubuntu-vm-datavolumetemplates.yaml.template` | `$SSH_PUBKEY` |

To expand a template: source `$LAB_ENV_FILE`, then `envsubst < foo.yaml.template > foo.yaml`.

## `$LAB_ENV_FILE`

A shell-sourceable file (default `~/.kubev-lab.env`) that exports every env var the scaffold needs:

```bash
# ~/.kubev-lab.env — created during Ch01 setup. Substitute your own values.
export CP_INTERNAL_IP="10.0.0.10"
export WORKER_INTERNAL_IP="10.0.0.11"
export METALLB_RANGE="10.0.0.220-10.0.0.224"
export SSH_KEY_PATH="/root/.ssh/id_ed25519"
export SSH_PUBKEY="$(cat ~/.ssh/id_ed25519.pub)"
export KKP_URL="https://kkp.demo.kubermatic.io/"
```

The values shown are placeholders — the course recording uses a GCP deployment with different IPs, but the contract is the same: every learner provides their own.

## Relationship to `cluster.yaml.template`

The template was generated by the installer itself:

```bash
kubermatic-virtualization config print \
    --enable-metallb --metallb-ip-range "$METALLB_RANGE" \
    --enable-longhorn \
    --control-plane-hosts 'address:$CP_INTERNAL_IP,sshUsername:root,sshPrivateKeyFile:$SSH_KEY_PATH' \
    --worker-hosts        'address:$WORKER_INTERNAL_IP,sshUsername:root,sshPrivateKeyFile:$SSH_KEY_PATH'
```

If the installer's schema changes (new fields, default changes), regenerate with the same flags and diff — do not hand-edit unless we're overriding a default intentionally.
